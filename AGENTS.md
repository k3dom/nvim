## Code style

### Comments

**Default to zero comments.** Write one only when the information is essential and
cannot be inferred from the code itself. If unsure, it is not needed.

### Functions

**Default to inlining logic.** Reading straight down and having logic be co-located
beats jumping between definitions. A function that is e.g. only used once or twice
and exists only to name a few lines is a cost, not a cleanup.

### Prose

Never use semicolons or em dashes to structure sentences in prose.
